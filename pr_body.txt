This PR groups several foundational tasks for Phase 2: Execution Tracing.

### 🚀 Changes

1. **Fixture SDK & Optimization** 
   - Added `[profile.release] opt-level = "z"` to the root `Cargo.toml` so the dummy contract is fully optimized for size when building as a WASM contract. (Closes #4)

2. **Memory Profiling Fixture**
   - Added `memory_heavy_loop` to `fixtures/dummy-contract/src/lib.rs`. This function dynamically allocates vectors in a loop to provide a non-trivial heap load for memory tracking and tracing tests. (Closes #6)

3. **Compilation Script**
   - Created `fixtures/build.sh` which encapsulates `cargo build --target wasm32-unknown-unknown --release` for the fixture contract. This allows contributors to build the test fixture without having to memorize the specific cargo flags. (Closes #7)

4. **Tracer Data Models**
   - Added standard `#[derive(Debug, Clone, PartialEq)]` traits to `EventType`, `TraceEvent`, `SourceFrame`, and `CallStackNode` in `src/models.rs`.
   - Included a unit test inside `src/models.rs` validating that `TraceEvent` equality functions properly. (Closes #8)

5. **Tracer State**
   - Scaffolded the core execution state for the profiler in `src/tracer.rs` by adding a pre-allocated `events: Vec<TraceEvent>` field to the `ExecutionTracer` struct.
   - Initialized the vector in `ExecutionTracer::new()` so it can be populated by host-level engine hooks in subsequent issues. (Closes #9)

6. **Roadmap Updates**
   - Updated `ROADMAP.md` to check off the newly completed milestones for Phase 2.
